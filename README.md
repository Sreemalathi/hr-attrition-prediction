# Employee Attrition Prediction

Predictive model that estimates which employees are likely to **resign voluntarily**, built with Python (pandas, scikit-learn) on a **simulated synthetic** HR dataset.

> **Purpose:** this is a learning project that demonstrates the modelling workflow. It is **not** a reliable forecast.

## Business question

Which employees are at higher risk of voluntarily resigning, and which factors are associated with that risk, so HR can decide where retention effort is worth spending?

## Data

- **1,600 simulated employees** who were employed at any point between Jan 2021 and Sep 2026 (450 of them were hired earlier, from 2011), across five departments and 19 team leads.
- **Simulated synthetic data**, generated by `generate_hr_dataset.py` (seed 42, reproducible).
- Full column descriptions: [`DATA_DICTIONARY.md`](data/DATA_DICTIONARY.md).

## Approach

1. **Prepared the data:** converted dates, built the target. Employees *terminated for cause* (104) were excluded, because they didn't choose to leave and a retention programme can't act on them. That leaves 1,496 employees, of whom 504 resigned (33.7%).
2. **Features:** `EngagementSurvey`, `EmpSatisfaction`, `OvertimeHoursPerMonth`.
3. **Split:** 80% training / 20% test (300 employees), stratified so both parts keep the 33.7% resignation share.
4. **Scaled** the features, fitting the scaler on training data only.
5. **Trained** a logistic regression and evaluated it on the test set with a confusion matrix, recall and precision.
6. **Compared decision thresholds** (30%, 40%, 50%).

## Results

| Threshold | Recall | Precision |
|---|---:|---:|
| 50% | 26.7% | 64.3% |
| 40% | 45.5% | 50.0% |
| 30% | 73.3% | 42.0% |

Lowering the threshold finds more leavers but raises false alarms. The right threshold depends on what HR can afford to do with each flag.

### Key findings

- At the default 50% threshold the model finds only 27 of the 101 employees in the test set who resigned (recall 26.7%), because the resignation rate is only about one in three. When it does flag someone, it is right 64.3% of the time (27 of 42).
- Lowering the threshold to 30% finds 74 of the 101 leavers (recall 73.3%), but it flags 176 employees and only 74 of them resigned (precision 42.0%): more leavers found, more false alarms.

## Limitations

- **Synthetic data.** The patterns were built in by the generator, so the model rediscovering them shows the workflow works, not that these drivers hold in a real company.
- **Not a forecast.** Engagement and overtime are the latest recorded values, which for leavers means *at exit*. A real forecasting model needs values as they were on a prediction date.
- **Thresholds were explored on the test set** to learn how they behave. In real work, choose the threshold on validation data and evaluate once on a separate test set.
- Gender and date of birth were deliberately **not** used as features.

## Next steps

- Add categorical features (department, manager, recruitment source) with one-hot encoding.
- Build point-in-time snapshots so tenure and other measures are known only up to the prediction date.
- Compare against a tree-based model, with cross-validation.
